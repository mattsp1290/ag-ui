# Events

The AG-UI Protocol SDK uses a streaming event-based architecture. Events are the
fundamental units of communication between agents and the frontend. This section
documents the event types and their properties in the Go SDK.

## Event Interface

All events implement the `Event` interface, which provides a common contract for
event handling:

```go
type Event interface {
    // Type returns the event type
    Type() EventType

    // Timestamp returns the event timestamp (Unix milliseconds)
    Timestamp() *int64

    // SetTimestamp sets the event timestamp
    SetTimestamp(timestamp int64)

    // ThreadID returns the thread ID associated with this event
    ThreadID() string

    // RunID returns the run ID associated with this event
    RunID() string

    // Validate validates the event structure and content
    Validate() error

    // ToJSON serializes the event to JSON for cross-SDK compatibility
    ToJSON() ([]byte, error)

    // GetBaseEvent returns the underlying base event
    GetBaseEvent() *BaseEvent
}
```

## BaseEvent

All events embed the `BaseEvent` struct, which provides common fields and
functionality:

```go
type BaseEvent struct {
    EventType   EventType `json:"type"`
    TimestampMs *int64    `json:"timestamp,omitempty"`
    RawEvent    any       `json:"rawEvent,omitempty"`
    Metadata    types.Metadata `json:"metadata,omitempty"`
}
```

| Field | Type | Description |
| ------------- | ---------------- | ---------------------------------------------------------------------------------- |
| `EventType` | `EventType` | The type of event (discriminator field) |
| `TimestampMs` | `*int64` | Timestamp when the event was created (Unix milliseconds) |
| `RawEvent` | `any` | Original event data if this event was transformed |
| `Metadata`    | `types.Metadata` | Optional arbitrary JSON metadata available on every event through `GetBaseEvent()` |

### Creating a Base Event

```go
import "github.com/ag-ui-protocol/ag-ui/sdks/community/go/pkg/core/events"

// Create a new base event with automatic timestamp
baseEvent := events.NewBaseEvent(events.EventTypeCustom)
```

`NewBaseEvent` sets the timestamp. Every concrete event constructor embeds it,
and every event implements all methods in `Event`, including `GetBaseEvent`. Use
that method for fields shared across concrete event types:

```go
func addTrace(event events.Event, traceID string) {
    event.GetBaseEvent().Metadata = types.Metadata{"traceId": traceID}
}
```

## Complete event catalogue

The Go package implements all 36 current event types. The constructors below are
the public entry points; `With...` options add optional fields without changing
the established simple constructors.

| Group                    | Events and constructors                                                                                                                                                                                                                                                                                                             |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Text                     | `TextMessageStart` (`NewTextMessageStartEvent`), `TextMessageContent` (`NewTextMessageContentEvent`, `NewTextMessageContentEventWithOptions`), `TextMessageEnd` (`NewTextMessageEndEvent`, `NewTextMessageEndEventWithOptions`), `TextMessageChunk` (`NewTextMessageChunkEvent`)                                                    |
| Tool                     | `ToolCallStart` (`NewToolCallStartEvent`), `ToolCallArgs` (`NewToolCallArgsEvent`, `NewToolCallArgsEventWithOptions`), `ToolCallEnd` (`NewToolCallEndEvent`, `NewToolCallEndEventWithOptions`), `ToolCallChunk` (`NewToolCallChunkEvent`), `ToolCallResult` (`NewToolCallResultEvent`)                                              |
| State and activity       | `StateSnapshot` (`NewStateSnapshotEvent`), `StateDelta` (`NewStateDeltaEvent`), `MessagesSnapshot` (`NewMessagesSnapshotEvent`), `ActivitySnapshot` (`NewActivitySnapshotEvent`), `ActivityDelta` (`NewActivityDeltaEvent`)                                                                                                         |
| Run                      | `RunStarted` (`NewRunStartedEvent`, `NewRunStartedEventWithOptions`), `RunFinished` (`NewRunFinishedEvent`, `NewRunFinishedEventWithOptions`), `RunError` (`NewRunErrorEvent`), `StepStarted` (`NewStepStartedEvent`, `NewStepStartedEventWithOptions`), `StepFinished` (`NewStepFinishedEvent`, `NewStepFinishedEventWithOptions`) |
| Reasoning                | `ReasoningStart`, `ReasoningMessageStart`, `ReasoningMessageContent`, `ReasoningMessageEnd`, `ReasoningMessageChunk`, `ReasoningEnd`, and `ReasoningEncryptedValue`, each with the corresponding `New...Event` constructor                                                                                                          |
| Subagent                 | `SubagentStarted` (`NewSubagentStartedEvent`), `SubagentFinished` (`NewSubagentFinishedEvent`), `SubagentError` (`NewSubagentErrorEvent`)                                                                                                                                                                                           |
| Escape hatches           | `Custom` (`NewCustomEvent`) and `Raw` (`NewRawEvent`)                                                                                                                                                                                                                                                                               |
| Deprecated compatibility | `ThinkingStart`, `ThinkingEnd`, `ThinkingTextMessageStart`, `ThinkingTextMessageContent`, and `ThinkingTextMessageEnd`, each with the corresponding constructor; prefer reasoning events for new producers                                                                                                                          |

Chunk events accept optional pieces and are useful when a producer cannot emit
the full start/content/end lifecycle separately. Activity deltas carry JSON
Patch operations. `REASONING_ENCRYPTED_VALUE` carries an opaque `encryptedValue`
for either a reasoning `message` or `tool`; consumers should forward it without
inspecting it.

Most stream events expose optional `SubagentRunID` attribution. Subagent
lifecycle events describe the invocation itself: start can include its parent
subagent and spawning tool/message, finish can include a result and a `success`
or `suspended` outcome, and error terminates the subagent independently of the
root run. A suspended subagent can be announced again with the same ID after the
client resumes the run.

The canonical definitions are the Go files in
[`pkg/core/events`](https://github.com/ag-ui-protocol/ag-ui/tree/main/sdks/community/go/pkg/core/events),
including the event constructors and their option functions.

## Text Message Events

These events handle streaming text message content from agents.

### TextMessageStartEvent

Signals the start of a streaming text message.

```go
type TextMessageStartEvent struct {
    *BaseEvent
    MessageID string  `json:"messageId"`
    Role      *string `json:"role,omitempty"`
}
```

| Field | Type | Description |
| ----------- | --------- | ------------------------------------------------------ |
| `MessageID` | `string` | Unique identifier for the message |
| `Role` | `*string` | Role of the message sender (e.g., "assistant", "user") |

**Usage Example:**

```go
// Create a text message start event
event := events.NewTextMessageStartEvent("msg-123", events.WithRole("assistant"))

// Handle the event
switch e := event.(type) {
case *events.TextMessageStartEvent:
    fmt.Printf("Message started: %s with role: %s\n", e.MessageID, *e.Role)
}
```

### TextMessageContentEvent

Contains a piece of streaming text message content.

```go
type TextMessageContentEvent struct {
    *BaseEvent
    MessageID string `json:"messageId"`
    Delta     string `json:"delta"`
}
```

| Field | Type | Description |
| ----------- | -------- | ----------------------------------------- |
| `MessageID` | `string` | ID of the message this content belongs to |
| `Delta` | `string` | The text content chunk |

**Usage Example:**

```go
// Create a content event
event := events.NewTextMessageContentEvent("msg-123", "Hello, world!")

// Handle streaming content
switch e := event.(type) {
case *events.TextMessageContentEvent:
    fmt.Print(e.Delta) // Stream the content to output
}
```

### TextMessageEndEvent

Signals the end of a streaming text message.

```go
type TextMessageEndEvent struct {
    *BaseEvent
    MessageID string `json:"messageId"`
}
```

| Field | Type | Description |
| ----------- | -------- | -------------------------------- |
| `MessageID` | `string` | ID of the message that has ended |

**Usage Example:**

```go
// Create an end event
event := events.NewTextMessageEndEvent("msg-123")

// Handle message completion
switch e := event.(type) {
case *events.TextMessageEndEvent:
    fmt.Printf("\nMessage %s completed\n", e.MessageID)
}
```

## Run Lifecycle Events

`RUN_STARTED` can carry `parentRunId` and the original `RunAgentInput`:

```go
started := events.NewRunStartedEventWithOptions(
    "thread-1",
    "run-2",
    events.WithParentRunID("run-1"),
    events.WithRunInput(input),
)
```

`RUN_FINISHED` accepts an optional result, usage, and discriminated outcome. Use
`WithSuccessOutcome()` for completion or `WithInterruptOutcome(interrupts)` for
a paused run; an interrupt outcome must contain at least one valid interrupt.
`RUN_ERROR` may carry partial usage. Omitted outcomes keep the legacy success
interpretation.

These events track the lifecycle of agent runs.

### RunStartedEvent

Signals the start of an agent run.

```go
type RunStartedEvent struct {
    *BaseEvent
    ThreadIDValue string `json:"threadId"`
    RunIDValue    string `json:"runId"`
}
```

| Field | Type | Description |
| --------------- | -------- | ----------------------------- |
| `ThreadIDValue` | `string` | ID of the conversation thread |
| `RunIDValue` | `string` | ID of the agent run |

**Usage Example:**

```go
// Create a run started event
event := events.NewRunStartedEvent("thread-789", "run-012")

// Handle run initiation
switch e := event.(type) {
case *events.RunStartedEvent:
    fmt.Printf("Run %s started in thread %s\n", e.RunID(), e.ThreadID())
}
```

### RunFinishedEvent

Signals the successful completion of an agent run.

```go
type RunFinishedEvent struct {
    *BaseEvent
    ThreadIDValue string      `json:"threadId"`
    RunIDValue    string      `json:"runId"`
    Result        interface{} `json:"result,omitempty"`
}
```

| Field | Type | Description |
| --------------- | ------------- | ------------------------------ |
| `ThreadIDValue` | `string` | ID of the conversation thread |
| `RunIDValue` | `string` | ID of the agent run |
| `Result` | `interface{}` | Result data from the agent run |

### RunErrorEvent

Signals an error during an agent run.

```go
type RunErrorEvent struct {
    *BaseEvent

```

| Field | Type | Description |
| ------------ | --------- | ---------------------------------------- |
| `Code` | `*string` | Error code |
| `Message` | `string` | Error message |
| `RunIDValue` | `string` | ID of the run that encountered the error |

**Usage Example:**

```go

event := events.NewRunErrorEvent(

    events.WithRunID("run-012"),

```

### Token usage helpers

Counts are `*int64`, so an explicit zero is different from an unreported count.
`TokenCount` makes that intent concise:

```go
usage := []events.TokenUsage{{
    Provider: "openai",
    Model: "example-model",
    InputTokens: events.TokenCount(0),
    OutputTokens: events.TokenCount(12),
}}
finished := events.NewRunFinishedEventWithOptions(
    "thread-1", "run-2", events.WithUsage(usage),
)
```

`AggregateTokenUsage` validates non-negative counts and groups by the exact
`(provider, model)` pair in first-seen order. It returns fresh pointers, checks
every sum for `int64` overflow, preserves unreported versus zero fields, and
never derives `totalTokens` from input and output counts.

`TokenUsageFromLangChainMetadata` reads only `input_tokens`, `output_tokens`,
`total_tokens`, `input_token_details.cache_read`, and
`output_token_details.reasoning`. It accepts Go integer types, `json.Number`,
and finite integral floats from `0` through `2^53-1`. Invalid fields are ignored
independently; strings, booleans, negative or fractional values, non-finite
floats, and out-of-range integers do not become counts. The helper returns `nil`
if no count survives, even when provider or model labels exist.

## State Management Events

These events handle state synchronization between agent and client.

### StateSnapshotEvent

Contains a complete snapshot of the state.

```go
type StateSnapshotEvent struct {
    *BaseEvent
    Snapshot any `json:"snapshot"`
}
```

| Field | Type | Description |
| ---------- | ----- | ----------------------- |
| `Snapshot` | `any` | Complete state snapshot |

**Usage Example:**

```go
// Create a state snapshot
state := map[string]interface{}{
    "currentStep": "processing",
    "progress": 75,
}
event := events.NewStateSnapshotEvent(state)
```

### StateDeltaEvent

Contains incremental state changes using JSON Patch operations (RFC 6902).

```go
type StateDeltaEvent struct {
    *BaseEvent
    Delta []JSONPatchOperation `json:"delta"`
}

type JSONPatchOperation struct {
    Op    string `json:"op"`              // "add", "remove", "replace", "move", "copy", "test"
    Path  string `json:"path"`            // JSON Pointer path
    Value any    `json:"value,omitempty"` // Value for add, replace, test operations
    From  string `json:"from,omitempty"`  // Source path for move, copy operations
}
```

| Field | Type | Description |
| ------- | ---------------------- | ------------------------------ |
| `Delta` | `[]JSONPatchOperation` | Array of JSON Patch operations |

**Usage Example:**

```go
// Create state delta with JSON Patch operations
delta := []events.JSONPatchOperation{
    {
        Op:    "replace",
        Path:  "/progress",
        Value: 100,
    },
    {
        Op:   "add",
        Path: "/completedAt",
        Value: time.Now().Unix(),
    },
}
event := events.NewStateDeltaEvent(delta)
```

## Event Decoding

The SDK provides an `EventDecoder` for parsing SSE events into typed Go structs:

```go
import (
    "github.com/ag-ui-protocol/ag-ui/sdks/community/go/pkg/core/events"
    "github.com/sirupsen/logrus"
)

// Create a decoder
logger := logrus.New()
decoder := events.NewEventDecoder(logger)

// Decode an SSE event
event, err := decoder.DecodeEvent("TEXT_MESSAGE_START", sseData)
if err != nil {
    log.Printf("Failed to decode event: %v", err)
    return
}

// Type-safe event handling
switch e := event.(type) {
case *events.TextMessageStartEvent:
    fmt.Printf("Message started: %s\n", e.MessageID)
case *events.TextMessageContentEvent:
    fmt.Printf("Content: %s\n", e.Delta)
case *events.ToolCallStartEvent:
    fmt.Printf("Tool call: %s\n", e.ToolCallName)
}
```

## Event Validation

All events support validation to ensure they conform to the protocol
specification:

### Individual Event Validation

```go
event := events.NewTextMessageStartEvent("")

// Validate the event
if err := event.Validate(); err != nil {
    // Handle validation error
    fmt.Printf("Invalid event: %v\n", err)
}
```

### Sequence Validation

The SDK can validate entire event sequences to ensure they follow the protocol
rules:

```go
// Validate a sequence of events
sequence := []events.Event{
    events.NewRunStartedEvent("thread-1", "run-1"),
    events.NewTextMessageStartEvent("msg-1"),
    events.NewTextMessageContentEvent("msg-1", "Hello"),
    events.NewTextMessageEndEvent("msg-1"),
    events.NewRunFinishedEvent("thread-1", "run-1"),
}

if err := events.ValidateSequence(sequence); err != nil {
    // Handle sequence validation error
    fmt.Printf("Invalid event sequence: %v\n", err)
}
```

Sequence validation ensures:

- Runs are started before they can be finished or errored
- Messages are started before content can be added or ended
- Tool calls follow the proper start → args → end lifecycle
- Events maintain referential integrity

## ID Generation

The SDK provides utilities for generating unique IDs:

```go
// Generate various ID types
threadID := events.GenerateThreadID()  // "thread-{uuid}"
runID := events.GenerateRunID()        // "run-{uuid}"
messageID := events.GenerateMessageID() // "msg-{uuid}"
toolCallID := events.GenerateToolCallID() // "tool-{uuid}"
stepID := events.GenerateStepID()      // "step-{uuid}"

// Use with event creation
event := events.NewRunStartedEvent(
    events.GenerateThreadID(),
    events.GenerateRunID(),
)
```
