# Types

`ag_ui_core::types` defines the wire model; `ag_ui_client::core::types` re-exports it.

## IDs and messages

`AgentId`, `ThreadId`, `RunId`, `MessageId`, and `ToolCallId` are opaque string IDs. Use `::random()` or convert an existing string with `::from(...)`. Wire IDs can be arbitrary strings, not just UUIDs.

`Role` has seven values: `Developer`, `System`, `Assistant`, `User`, `Tool`, `Activity`, and `Reasoning`. `Message` has a variant for each. `Message::new_user`, `new_system`, `new_developer`, and `new_assistant` are useful for text. `Message::content()` returns `Option<&str>`: multimodal user or tool content is not flattened to text.

User and tool messages use `MessageContent::Text(String)` or `MessageContent::Parts(Vec<ContentPart>)`. Parts are `Text`, `Image`, `Audio`, `Video`, and `Document`. Media parts carry a `PartSource::Data`, `Url`, or `File`; a text part carries text. Parts may have IDs and metadata. Tool messages also carry a tool call ID. Activity messages carry an activity type and structured content; reasoning messages carry reasoning text.

## Run input and control

`RunAgentInput<StateT, FwdPropsT>` carries `thread_id`, `run_id`, state, messages, optional tools/context, forwarded props, and optional `protocol_version`, `parent_run_id`, and `resume`. `Agent::run_agent` constructs this from `RunAgentParams` and sets protocol version `1.0`. `RunAgentParams::with_resume(Vec<ResumeEntry>)` answers pending interrupts; each entry has an interrupt ID, `ResumeStatus::Resolved` or `Cancelled`, and optional payload and metadata.

`RunFinishedOutcome` models success, interrupt, and cancellation. `SubagentFinishedOutcome` models success or suspension. `TokenUsage` reports optional token counts and provider/model. `AgentCapabilities` describes optional identity, transport, tool, output, state, multi-agent, reasoning, multimodal, execution, and human-in-the-loop support.

## State patches

`StateDeltaEvent::delta` and `ActivityDeltaEvent::patch` use `Vec<JsonPatchOperation>`, with add, remove, replace, move, copy, and test operations. `JsonPointer` represents patch paths. `StateSnapshotEvent<StateT>` contains typed state; your `StateT` implements `AgentState` (`Serialize`, `Deserialize`, `Clone`, `Debug`, `Send`, and `Sync`).

See [events](/sdk/rust/core/events) and [the agent API](/sdk/rust/client/agent-trait).

## Constructing an input

```rust
use ag_ui_core::types::{Message, RunAgentInput, RunId, ThreadId};
use serde_json::json;

let input = RunAgentInput::new(
    ThreadId::random(),
    RunId::random(),
    json!({}),
    vec![Message::new_user("Hello")],
    vec![], // Tool definitions
    vec![], // Context entries
    json!({}), // forwarded props
);
```

`Tool` supplies a name, description, and JSON Schema parameters. `Context` supplies a description and value. The client builder has `add_tool`, `add_context`, `with_state`, `with_forwarded_props`, `add_message`, and `user` helpers. Typed state and forwarded props can be supplied with `RunAgentParams::<State, Props>::new_typed()`.
